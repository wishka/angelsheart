# Ангел-Хранитель — приложение для Android на Kotlin

Приложение сообщества взаимопомощи: лента, люди, чаты и группы, а
также кошелёк, переводы и сборы. Экраны написаны на Kotlin и Jetpack
Compose, данные берутся с Django по HTTP.

Нижняя панель: **Лента · Люди · Чаты · Группы · Профиль**. После входа
открывается лента. Деньги (кошелёк, перевод, сборы, история,
верификация) — в «Профиле».

Это **не** прежняя обёртка сайта: браузера внутри нет, интерфейс
нарисован средствами Android.

## Собрать APK

### Без своей машины: GitHub Actions

После каждого push в репозиторий GitHub собирает отладочный APK сам
(`.github/workflows/ci.yml`) и заодно гоняет тесты сервера. Готовый
файл: вкладка **Actions** → последний запуск → **Artifacts** →
`angelsheart-debug-apk`. Если сборка упала, текст ошибки там же — его
можно прислать как есть.

Подписанные выпуски (APK и AAB) собираются по тегу `vX.Y.Z` и
публикуются в GitHub Releases и на сайте — весь процесс, ветки и
секреты описаны в `docs/CICD.md`. Release-сборка ходит на рабочий
сервер только по HTTPS; отладочная — на `127.0.0.1` и разрешает HTTP.

Собирать нужно на машине с интернетом: Gradle скачивает Android SDK и
библиотеки с `dl.google.com` и Maven Central. В среде, где писался код,
эти адреса закрыты политикой сети — поэтому готового APK в комплекте нет.

### Через Android Studio (проще)

1. Установить Android Studio (если ещё не стоит).
2. **File → Open** → выбрать папку `android-kotlin` (каталог этого проекта).
3. Студия сама предложит скачать Android SDK 35 и Build Tools —
   согласиться. Это разовая загрузка около 2 ГБ.
4. **Build → Build Bundle(s) / APK(s) → Build APK(s)**.
5. Готовый файл: `app/build/outputs/apk/debug/app-debug.apk`.

### Из командной строки

```bash
cd android-kotlin        # каталог этого проекта

# Один раз: указать, где лежит Android SDK
echo "sdk.dir=$HOME/Library/Android/sdk" > local.properties

./gradlew assembleDebug
```

Результат — `app/build/outputs/apk/debug/app-debug.apk`.

Нужна **JDK 17** (`java -version`). На JDK 21 сборка тоже проходит,
на JDK 11 — нет.

### Поставить на телефон

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Или скопировать APK на телефон и открыть его — Android спросит
разрешение ставить приложения из этого источника.

## Подключить к локальному серверу

**Главная тонкость: на телефоне `localhost` — это сам телефон**, а не
ваш компьютер. Django, запущенный на ноутбуке, по этому адресу с
телефона не виден. Отсюда три рабочих способа.

### Телефон по кабелю — рекомендую

```bash
# на компьютере
python manage.py runserver          # слушает 127.0.0.1:8000, как обычно
adb reverse tcp:8000 tcp:8000       # телефон пробросит свой порт 8000 сюда
```

В приложении адрес оставить `http://127.0.0.1:8000/` (он стоит по
умолчанию). Ничего в настройках Django менять не нужно: заголовок Host
приходит как `127.0.0.1`, и `ALLOWED_HOSTS` его уже разрешает.

`adb reverse` нужно повторять после каждого переподключения кабеля.

### Эмулятор

```bash
python manage.py runserver 0.0.0.0:8000
```

В `.env`: `ALLOWED_HOSTS=localhost,127.0.0.1,10.0.2.2`

В приложении: **Настройки → Эмулятор — 10.0.2.2:8000**. Это адрес,
по которому эмулятор видит хозяйскую машину.

### По Wi-Fi

```bash
python manage.py runserver 0.0.0.0:8000
ipconfig getifaddr en0        # адрес компьютера в сети, например 192.168.1.42
```

В `.env`: `ALLOWED_HOSTS=localhost,127.0.0.1,192.168.1.42`

В приложении: адрес `http://192.168.1.42:8000/`. Телефон и компьютер
должны быть в одной сети, и брандмауэр не должен резать порт.

## Демо-режим

**Настройки → Демо-режим.** Приложение перестаёт ходить в сеть и берёт
выдуманные данные из памяти: можно пролистать все экраны без сервера,
войти с любым именем и паролем, перевести деньги и увидеть, как
меняется баланс.

Переключение выбрасывает из учётной записи — намеренно: токен одного
режима в другом бессмыслен, и попытка им воспользоваться дала бы 401
на каждом экране, то есть выглядела бы как поломка приложения.

## Что откуда берётся

Заглушек больше нет: каждый экран работает с настоящим API.

| Экран | API |
|---|---|
| Вход, регистрация | `/api/auth/…`, JWT с обновлением токена |
| Восстановление пароля | `/api/auth/password-reset/` — письмо со ссылкой, пароль задаётся в браузере |
| Лента, записи, «нравится», комментарии, жалобы | `/api/feed/`, `/api/posts/…` |
| Подписки, записи человека | `/api/people/<id>/follow/`, `/api/people/<id>/posts/` |
| Люди: поиск по имени, городу, полу, возрасту, интересам | `/api/people/` |
| Своя анкета и видимость в поиске | `/api/profile/` |
| Чаты, правка и удаление своих сообщений | `/api/chats/…`, опрос раз в 4 секунды (`?changed_since=` приносит правки) |
| Группы, заявки, роли, передача владения | `/api/groups/…` |
| Чёрный список, жалобы на сообщения | `/api/blocks/`, `/api/chats/<id>/messages/<id>/report/` |
| Кошелёк: баланс, оборот, операции | `/api/dashboard/`, `/api/wallet/`, `/api/transactions/` |
| Пополнение | `/api/wallet/topup/` — страница оплаты ЮKassa открывается в браузере, деньги приходят по вебхуку |
| Вывод: карта, СБП, ЮMoney; отмена заявки | `/api/wallet/withdrawals/…` — те же проверки, что на сайте |
| Верификация: паспорт и сканы документов | `/api/verification/…` — на проверку администратору |
| Сборы, пожертвования, перевод, лидеры, согласия | `/api/fundraises/…`, `/api/transactions/transfer/` и др. |

Длинные списки подгружаются кнопкой «Показать ещё»: лента, комментарии
и переписка — курсором «до id», остальное — номерами страниц.

## Как всё устроено

```
app/src/main/java/ru/angelhelper/app/
  MainActivity.kt         единственный экран Android, разводка по экранам
  data/
    Models.kt             данные и тип результата
    Api.kt                интерфейс: что приложение просит у сервера
    HttpApi.kt            настоящий HTTP к Django
    DemoApi.kt            демо-режим: деньги, сборы, кошелёк
    DemoSocial.kt         демо-режим: люди, чаты, группы
    DemoFeed.kt           демо-режим: лента и подписки
    FeedModels.kt         лента, страницы списков, кошелёк
    Session.kt            настройки и токены
  ui/
    AppViewModel.kt       состояние приложения и переходы
    Theme.kt              цвета сайта
    Components.kt         поля, кнопки, карточки
    screens/              экраны (FeedScreens.kt — лента и записи)
app/src/test/            юнит-тесты на JVM: ./gradlew testDebugUnitTest
```

Зависимостей намеренно мало: ни Retrofit, ни Moshi, ни Navigation.
HTTP — на `HttpURLConnection`, разбор ответов — на `org.json`, переходы
между экранами — своим стеком в модели. Всё это входит в саму платформу
Android, то есть не может разойтись по версиям и ничего не нужно
скачивать сверх Compose. Для приложения, которое собирают на чужой
машине, это важнее краткости кода.

Единственное исключение — `firebase-messaging` для push-уведомлений:
доставлять уведомления закрытому приложению без него на Android нельзя.
Фото грузятся и кэшируются своим кодом (`ui/Images.kt`), без Coil.

## Тесты

`app/src/test/` — юнит-тесты, которые идут без эмулятора и запускаются в
CI после сборки:

```bash
./gradlew testDebugUnitTest
```

Они проверяют правила демо-режима (лента, подписки, правка сообщений,
роли в группах, кошелёк, верификация) — демо повторяет правила сервера,
и расхождение выглядело бы как ошибка приложения, — а также склейку
страниц и модели. Серверные правила проверяют тесты Django
(`social/tests.py`, `main/test_wallet_api.py`).

## Известные упрощения

* **Незашифрованный HTTP разрешён для всех адресов**
  (`res/xml/network_security_config.xml`). Это тестовая сборка, и адрес
  сервера человек задаёт сам. Для боевой сборки файл нужно заменить на
  точечный список или убрать вовсе — там весь обмен идёт по HTTPS.
  (Точечный список я пробовал, но конфигурация сетевой безопасности
  Android не поддерживает диапазоны адресов, и Wi-Fi переставал
  работать.)
* **Согласия при регистрации — одним флажком**, хотя на сайте это три
  отдельных документа с разными правовыми основаниями. Сервер всё равно
  требует оба обязательных.
* **Состояние демо-режима живёт до перезапуска приложения** и не
  сбрасывается при выходе: потратив в демо деньги и выйдя, вы увидите
  прежний уменьшенный баланс.

## Сообщество: люди, чаты, группы

Серверная часть — отдельное Django-приложение `social` (модели,
миграции, тесты `python manage.py test social`). Нижняя панель теперь:
Главная · Сборы · Люди · Чаты · Профиль. Перевод и история остались на
«Главной»; перевести человеку можно и прямо из его анкеты или чата.

**Поиск людей.** Находятся только те, кто сам включил «Показывать меня
в поиске» в анкете (Профиль → Анкета в сообществе). Этот переключатель
— согласие на распространение персональных данных (ст. 10.1 152-ФЗ):
сервер записывает его так же, как при регистрации, а отзыв согласия
на сайте сразу убирает анкету из поиска. Почта и баланс в анкете не
показываются никогда. Написать можно и тому, кого нет в поиске, — по
точному логину, как при переводе.

**Чаты.** Один логин — личный чат (второй раз создаётся не новый, а
открывается прежний). Несколько логинов — групповой чат с названием.
Новые сообщения открытый чат запрашивает раз в 4 секунды; для этого у
API сообщества своя ставка ограничения запросов (`social`, 2000 в час)
— общей ставки в 1000 запросов в сутки хватило бы на час переписки.

**Группы.** Открытая — вступление сразу, закрытая — по заявке, которую
принимает владелец или администратор. У каждой группы своё обсуждение:
оно появляется в «Чатах» у всех участников. Список участников видят
только участники. Владелец выйти не может.

**Удаление учётной записи** стирает анкету, участие в чатах и группах;
сообщения остаются у собеседников как «Сообщение удалено», группа
переходит следующему участнику.

**Чёрный список.** Заблокировать можно из анкеты человека или из меню
личного чата (⋮), список — в Профиле → Чёрный список. Блокировка
действует в обе стороны: личная переписка закрыта для обоих (историю
прочитать можно), в поиске друг друга не видно, новый чат не создать.
В общих чатах сообщения заблокированного скрыты — сервер подменяет
текст, а не просит приложение его спрятать. О блокировке человеку не
сообщается: он видит лишь «Пользователь ограничил переписку с вами».

**Жалобы.** Долгое нажатие на чужое сообщение → причина (спам,
оскорбления, мошенничество, запрещённый контент, другое), комментарий и
галочка «заблокировать автора». Текст сообщения копируется в жалобу —
он сохранится, даже если автор удалит учётную запись. После трёх жалоб
от разных людей сообщение скрывается до решения модератора
(`REPORTS_TO_HIDE` в `social/services.py`). Модератор работает в
админке: «Жалобы на сообщения» → действие «Принять: скрыть сообщение»
или «Отклонить: оставить сообщение». Ограничить автора — в разделе
ограничений учётных записей, там же уходит уведомление с причиной.

**Фото.** Фото анкеты — Профиль → Анкета в сообществе → «Выбрать
фото»; фото в чат — кнопка «+» слева от поля ввода. Выбор через
системный выбор фото Android: разрешение на доступ ко всей галерее
не нужно. Снимок уменьшается на телефоне (до 1024/1600 точек) и
поворачивается по метке ориентации; сервер пересохраняет его ещё раз,
срезая все метаданные — включая координаты места съёмки. Файлы лежат
в приватном хранилище: фото анкеты видят те, кому видна анкета, и
собеседники по чатам; фото из чата — только участники.

**Уведомления.** О новых сообщениях приходят push-уведомления через
Firebase Cloud Messaging. Через Google идёт только номер чата —
приложение само забирает с нашего сервера, от кого и что пришло, и
показывает уведомление. Текст переписки за рубеж не уходит. Пока чат
открыт, уведомления о нём не показываются; нажатие на уведомление
открывает чат. Разрешение (Android 13+) спрашивается один раз после
входа.

Как включить:

1. [console.firebase.google.com](https://console.firebase.google.com) →
   создать проект → добавить Android-приложение с пакетом
   `ru.angelhelper.app` (и `ru.angelhelper.app.debug` для отладочной
   сборки).
2. Скачать `google-services.json` и положить в `android-kotlin/app/`.
   В репозиторий он не попадает (`.gitignore`); для сборки на GitHub
   его содержимое кладётся в секрет `GOOGLE_SERVICES_JSON`.
3. На сервере: Настройки проекта → Сервисные аккаунты → «Создать
   закрытый ключ». В `.env`: `FCM_PROJECT_ID=<id проекта>` и
   `FCM_CREDENTIALS_FILE=<путь к ключу>`; `pip install -r requirements.txt`.

Без этих шагов приложение собирается и работает как прежде, просто без
уведомлений.

**Токены входа** хранятся зашифрованными ключом AES из AndroidKeyStore
(`data/TokenCipher.kt`): в файле настроек — только шифротекст, ключ из
хранилища не извлекается. Токены прежней версии перешифровываются при
первом запуске.

### Чего пока нет

* Ленту и переписку нужно подгружать кнопкой — бесконечной прокрутки нет:
  экран лежит в общей прокрутке, и ленивый список внутри неё невозможен.
* Фото в записи — одно; видео и опросов нет.
* Уведомления приходят только о сообщениях, не о комментариях и подписках.
