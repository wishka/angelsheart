# Сборка приложения для Android

Приложение — это сайт, упакованный в APK (Trusted Web Activity). Внутри
нет второй реализации правил про деньги: экран приложения показывает те
же страницы того же сервера. Значит, правка на сайте доходит до всех
установленных приложений сразу, а пересборка нужна только при смене
значка, названия или домена.

Собирать нужно на машине с интернетом: инструменты скачивают Android SDK
и JDK. В песочнице, где писался код, внешние адреса закрыты.

---

## 0. Перед сборкой: заменить домен

В `twa-manifest.json` сейчас стоит `angelhelper.ru` — замените его на
боевой домен **везде** (`host`, `startUrl`-адреса иконок, `webManifestUrl`,
`fullScopeUrl`). Приложение открывает ровно тот домен, который здесь
записан, и ошибку в нём видно только на установленном телефоне.

Сайт должен работать по HTTPS с действительным сертификатом. По HTTP
Trusted Web Activity не запускается вовсе.

## 1. Установить Bubblewrap

```bash
npm install -g @bubblewrap/cli
```

При первом запуске он предложит скачать Android SDK и JDK — согласитесь,
это разовая операция (около 1,5 ГБ).

## 2. Собрать

```bash
cd android
bubblewrap init --manifest https://ВАШ-ДОМЕН/manifest.webmanifest
# Bubblewrap задаст вопросы и перезапишет twa-manifest.json.
# Ответы уже подготовлены в нашем файле — сверьтесь с ним,
# особенно: уведомления — нет, ориентация — default.

bubblewrap build
```

Ориентация `default` намеренно совпадает с `orientation: 'any'`
в манифесте сайта: иначе установка из браузера запирала бы экран
в портрет, а установка из APK — нет.

На первой сборке Bubblewrap создаст ключ подписи `android.keystore`
и спросит пароли.

> **Ключ подписи — невосстановимый.** Потеряв его, обновить уже
> установленное приложение нельзя: Android откажется ставить сборку
> с другой подписью поверх старой, и людям придётся удалять приложение
> и ставить заново. Сохраните `android.keystore` и пароли отдельно от
> проекта — в менеджере паролей или в резервной копии, — и **не кладите
> их в репозиторий**.

Результат: `app-release-signed.apk`.

## 3. Прописать отпечаток ключа на сайте

Без этого шага приложение откроется, но поверх страницы будет видна
адресная строка браузера — вид «сайт в обёртке», а не приложение.

Отпечаток Bubblewrap печатает в конце сборки. Получить его вручную:

```bash
keytool -list -v -keystore android.keystore -alias angelsheart \
  | grep 'SHA256:'
```

Строку вида `AA:BB:CC:...` (64 пары символов) положите в `.env` сервера:

```
ANDROID_PACKAGE_NAME=ru.angelhelper.app
ANDROID_SIGNING_FINGERPRINTS=AA:BB:CC:...
```

Несколько ключей (например, отладочный и выпускной) перечисляются через
запятую.

Проверить: `https://ВАШ-ДОМЕН/.well-known/assetlinks.json` должен
отдавать JSON с вашим отпечатком — **по HTTPS и без перенаправлений**.
Пока переменная пуста, адрес отдаёт 404 намеренно: неверный отпечаток
хуже отсутствующего, потому что приложение молча покажет адресную
строку, и причину будут искать неделю.

## 4. Выложить APK

```
ANDROID_APK_PATH=/srv/app-release/angelsheart.apk
ANDROID_APP_VERSION=1.0.0
ANDROID_APK_INTERNAL_LOCATION=/internal-apk/angelsheart.apk
```

Скопируйте подписанный APK по этому пути. Страница `/app/` сама увидит
файл, покажет его размер, контрольную сумму SHA-256 и кнопку скачивания;
пока файла нет, она предлагает только установку из браузера.

**`ANDROID_APK_INTERNAL_LOCATION` в проде обязательна.** Без неё файл
отдаёт Django: рабочий процесс занят на всё время передачи, и десяток
телефонов на мобильной сети кладут сайт. С ней Django только решает,
отдавать ли, а файл передаёт nginx — быстро и с докачкой:

```nginx
location /internal-apk/ {
    internal;
    alias /srv/app-release/;
}
```

**Версию обновляйте вместе с файлом.** `ANDROID_APP_VERSION` ни на что
не смотрит: положив новую сборку и забыв переменную, вы раздадите файл
под именем предыдущей версии. Контрольная сумма на странице считается
по настоящему файлу и обновится сама.

## 5. Проверить на телефоне

1. Установить APK, открыть — адресной строки быть не должно.
2. Войти, открыть «Историю» — данные грузятся.
3. Включить авиарежим — должна появиться полоса «Нет соединения»
   и страница-заглушка вместо белого экрана; кнопки отправки форм
   становятся неактивными.
4. Выключить авиарежим — полоса исчезает.

## Новая версия

1. Поднять `appVersionName` и `appVersionCode` в `twa-manifest.json`
   (**код версии обязан расти** — иначе Android откажется обновлять).
2. `bubblewrap build` тем же ключом.
3. Положить новый APK по тому же пути, обновить `ANDROID_APP_VERSION`.
4. Сверить контрольную сумму на `/app/` с суммой собранного файла
   (`sha256sum app-release-signed.apk`).

Пересборка нужна только при смене значка, названия, домена или версии.
Содержимое приложения обновляется вместе с сайтом.

## Чего в приложении нет намеренно

**Push-уведомлений.** Они работают на Android через сервис Google (FCM):
адрес устройства и метка подписки уходят на серверы Google в США. Мы
только что убрали такую передачу данных из сайта — шрифты и значки
теперь свои, — и возвращать её ради уведомлений не станем. О событиях
на счёте сервис пишет на почту.

**Google Play.** Раздача идёт напрямую с сайта: при установке Android
покажет предупреждение о неизвестном источнике — это нормально для
любого APK не из магазина, и страница `/app/` объясняет это человеку.
Публикация в Play потребует аккаунта разработчика, проверки политики
для финансовых приложений и передачи ключа подписи Google.
