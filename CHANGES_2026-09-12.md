# «Ангел-Хранитель» — что исправлено

**Дата:** 12 сентября 2026
**Целевая архитектура:** номинальный счёт (ст. 860.1 ГК)
**Проверка:** 54 теста, `manage.py check --deploy` — ноль замечаний

---

## Как это проверять

```bash
pip install -r requirements.txt
cp .env.example .env            # ключи уже сгенерированы в вашем .env
python manage.py migrate
python manage.py test main      # 54 теста
```

Перед применением миграций сделана резервная копия базы:
`db.sqlite3.backup-20260912-150936`. Миграции `0010` и `0011` обратимы
по схеме, но `0011` шифрует данные и обратно их не расшифровывает —
откат схемы оставит зашифрованные значения.

⚠️ **Ключ шифрования.** В `.env` сгенерирован новый `ENCRYPTION_KEY`.
Паспортные данные зашифрованы именно им. Потеря ключа = потеря данных;
смена ключа требует перешифровки. Вынесите его в секрет-хранилище до прода.

## 1. Критические уязвимости

### Подделка вебхуков — закрыто

`payment_webhook` больше не доверяет телу запроса. Порядок такой: проверка,
что запрос пришёл с IP-диапазона ЮKassa, затем **повторный запрос платежа
через API** — статус и сумма берутся из ответа API, а не из уведомления.
Плюс сверка суммы с той, на которую пользователь оформил платёж, и
идемпотентность (ЮKassa повторяет доставку при таймауте).

Воспроизведено до: POST без авторизации → +50 000 ₽.
Сейчас: `HTTP 403`, баланс не меняется.

Новый файл `main/payments/webhooks.py`, диапазоны IP в
`settings.YOOKASSA_WEBHOOK_IPS` (сверьте с документацией перед продом —
ЮKassa их иногда меняет).

### Крипто-вебхук — удалён вместе с модулем

Он брал сумму зачисления прямо из тела запроса. Удалены `crypto.py`,
модели `CryptoBalance`/`CryptoTransaction`, страница крипто-баланса и
способ оплаты. Причина не только техническая: запрет на приём цифровой
валюты как встречного предоставления сохранён в 282-ФЗ с 01.09.2026.

### Хранение паспортов и карт — зашифровано

Новое поле `EncryptedTextField` на Fernet (`main/utils/fields.py`).
Проверено: в базе лежит `enc:v1:gAAAAAB...`, через ORM читается исходное
значение. Реквизиты выплат — `EncryptedJSONField`, в списках показывается
только маска (`****1111`).

Data-миграция `0011` зашифровала существующие записи, включая реальные
паспортные данные в вашей базе.

Оговорка: `full_name` оставлено открытым — по нему идёт поиск в админке,
а Fernet недетерминирован. Если ФИО тоже нужно шифровать, поиск придётся
строить на отдельном хеш-поле.

### Сканы документов — вне публичного каталога

`private-media/` вместо `media/kyc/`, выдача через `main:kyc_document`
с проверкой прав. При типовой настройке nginx паспорта больше не лежат
по угадываемому URL.

### `.env` — убран из git

`git rm --cached .env` выполнен, `.gitignore` расширен. **Коммит не делал** —
изменение в индексе, зафиксируете сами. Из индекса также убраны 10 файлов
`.pyc`. Ключи в `.env` перегенерированы: старые считайте скомпрометированными,
раз они были в истории.

### Секреты без небезопасных умолчаний

`DEBUG` по умолчанию `False`. При `DEBUG=False` отсутствие `SECRET_KEY`,
`ENCRYPTION_KEY`, `ALLOWED_HOSTS`, `POSTGRES_DB` или `REDIS_URL` роняет
запуск с внятным сообщением вместо тихого старта с публично известным ключом.

## 3. Утечки персональных данных

* `UserSerializer` больше не содержит `email` и `balance`. Для своего
  профиля — отдельный `CurrentUserSerializer` на `/api/users/me/`.
* `/api/leaders/` требует авторизации (было `AllowAny`) и не отдаёт балансы.
* `/api/search-users/` не возвращает email, ищет по началу имени.
* `/profile/<username>/` не показывает чужой баланс и чужую историю —
  ни во вью, ни в шаблоне.
* `check_username` перешёл с `icontains` на `iexact`: на запрос «a» больше
  не отвечает `exists: true`.
* `FundraiseDetailSerializer` — явный список полей вместо `__all__`.
* Анонимность донора теперь соблюдается на сервере, а не флагом для фронтенда.

## 5. Финансовая логика

**Единая точка входа.** Логика была скопирована в четырёх местах и везде
отличалась. Теперь это `main/services.py`: `transfer`, `donate`,
`refund_donations`, `hold_for_withdrawal`, `credit_payment`.

**Гонки.** Проверка достаточности средств выполняется **после**
`select_for_update()`, внутри той же транзакции. Балансы блокируются в
порядке возрастания `user_id` — иначе встречные переводы дают взаимную
блокировку. Сбор тоже блокируется: параллельные донаты затирали
`current_amount` друг друга.

**Ограничение в базе.** `CheckConstraint(amount >= 0)` на `Balance` —
последний рубеж, если проверку в коде когда-нибудь обойдут.

**Лимиты верификации работают.** Неверифицированный пользователь получает
отказ на выводе сверх 500 ₽ (воспроизведено до исправления: заявка на
100 000 ₽ проходила). Добавлен дневной лимит пополнения.

**KYC перестал быть фикцией.** Ввод паспорта больше не повышает уровень —
он фиксируется как поданный, уровень присваивает администратор и только
при наличии подтверждённого документа.

**Возврат при отмене сбора.** Отмена теперь обязательно возвращает деньги
донорам. Если автор успел потратить часть — возвращается доступное, недостача
логируется и показывается обеим сторонам. Отмена переведена на POST: при GET
её можно было вызвать чужой картинкой на стороннем сайте.

**Комиссия.** Одна ставка `DONATION_COMMISSION_PERCENT` из настроек, одна
реализация для веба и API. Удержанное фиксируется в `CommissionTransaction`
(раньше 3 % в API просто исчезали из системы). **Ставка стоит 0 %, как в коде,
а оферта обещает 3 % — это расхождение надо закрыть с юристом: либо правкой
оферты, либо переменной окружения.**

**Симуляция пополнения** доступна только при `DEBUG=True` и ограничена
суммарным потолком. Раньше два запроса давали 200 000 ₽ из ничего.

**Выплаты реально выполняются.** Действие «Завершить» просто меняло статус,
не переводя денег. Теперь админ-действие вызывает `MassWithdrawalService`,
а `list_editable` по статусу убран — правка в списке обходила методы
возврата средств.

* Все 37 вызовов `mark_safe` заменены на `format_html`. Проверено тестом:
  сбор с названием `<img src=x onerror=alert(1)>` попадает на страницу
  экранированным.
* Поиск по зашифрованным полям убран — он молча возвращал бы пустоту.
* Верификация выдаётся только при подтверждённом документе, вместо одного
  действия «сделать всем full».
* Массовая правка статусов транзакций удалена: она меняла журнал, не трогая
  балансы, из-за чего история расходилась с остатками.

## 7. Инфраструктура и код

* `requirements.txt` и `.env.example` — раньше воспроизвести окружение было
  нельзя, пакеты подбирались вручную.
* `main/tests.py`: было 3 строки, стало 54 теста. Каждый дефект из аудита
  закрыт тестом, который упал бы на старом коде.
* PostgreSQL обязателен при `DEBUG=False`: на SQLite `select_for_update()`
  не создаёт блокировок, и вся защита от гонок существует только на бумаге.
* Redis обязателен при `DEBUG=False`: счётчики попыток входа в `LocMemCache`
  живут внутри одного воркера, и перебор обходился попаданием в соседний.
* Индексы на часто фильтруемых полях, `CONN_MAX_AGE`.
* Удалён мёртвый код: `sbp.py`, `stripe.py`, дубль `MockPaymentProvider`,
  псевдонимы `SBPProvider`/`StripeProvider` (из-за них выплата «через Stripe»
  уходила в заглушку и рапортовала об успехе).
* Внутренние тексты ошибок больше не показываются пользователю — в лог.

## Что осталось и почему

**Ждёт перехода на номинальный счёт.** Модель `Balance` пока остаётся: она
безопасна, но юридически это по-прежнему ЭДС. Снимать её имеет смысл вместе
с открытием номинального счёта, потому что переписывать придётся ту же
область кода. Что изменится: `Balance` исчезает, `WithdrawalRequest`
становится распоряжением бенефициара, пополнение «про запас» пропадает.
Заявки на вывод, сборы, донаты, история и админка переживут переход
практически без правок — они уже вынесены в сервисный слой.

**Требует вашего решения, а не кода:**

1. Расхождение оферты (3 %) и кода (0 %).
2. Политика конфиденциальности перечисляет 5 видов данных из 15 собираемых
   и утверждает, что данные не передаются третьим лицам — хотя передаются.
3. Уведомление Роскомнадзора об обработке ПДн (ст. 22 152-ФЗ).
4. Раздельные согласия по ст. 9 и 10.1 — сейчас три чекбокса в одной форме.
5. Реквизиты владельца сайта (ч. 2 ст. 10 149-ФЗ).
6. Возрастное ограничение 18+ в оферте.
7. Модерация сборов: проверка цели и документов.
8. Вопросы юристу и банку — список в `ARCHITECTURE_2026-09-12.md`, раздел 6.

**Проверить перед продом:**

* Актуальность IP-диапазонов ЮKassa в `YOOKASSA_WEBHOOK_IPS`.
* `BEHIND_PROXY=True` и `TRUSTED_PROXY_COUNT` под вашу схему nginx —
  иначе блокировка по IP будет считать всех одним адресом.
* `ENCRYPTION_KEY` в секрет-хранилище, а не в файле на диске.
* nginx не должен отдавать `private-media/`.
